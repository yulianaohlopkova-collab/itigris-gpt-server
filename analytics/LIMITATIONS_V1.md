# Analytics MVP v1 — Data Limitations

Этот слой (sales analytics / management intelligence) в v1 читает **ручную XLSX-выгрузку** из ODL dashboard и строит:

- `management.md`
- `trainers.md`
- `signals_*.json`
- `actions_*.json`

## Критичные ограничения источника (05.2026)

1. **Линзы / фотохромы**

- В `ODL. Дашборд.xlsx` лист `линзы 05.2026` в текущей выгрузке не содержит рассчитанных pivot-значений (по сути только заголовки).
- Реальные значения по линзам присутствуют в PDF-выгрузке, но в v1 мы **не** строим парсер PDF, чтобы не добавлять хрупкую логику.
- Для автоматического анализа линз нужен **табличный экспорт** (XLS/CSV) или DataLens export с рассчитанными pivot-значениями.

Следствие: линзы исключены из mix/signals/actions v1 (кроме тех метрик, которые есть в других листах XLS, например `консопто 05.2026`).

2. **Гибкость к переименованиям**

- В v1 используется fuzzy/contains выбор KPI-блоков по заголовкам.
- Если заголовки радикально поменяются, потребуется обновить набор needles/правил выбора.

## Что нужно для v2 (auto-ingestion)

Цель v2: заменить только ingestion (источник данных), сохранив контракт `MonthFacts` и весь слой signals/reports/actions.

Минимальные требования к автоматическому источнику:

- табличные данные по линзам/фотохрому (не PDF)
- стабильные именования полей/мер
- доступ к недельной разбивке I–V внутри месяца
